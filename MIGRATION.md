# Linode Migration Guide: PDF-to-Slides

Migrate the entire stack (Presenton + Node app + TTS + slide renderer) and all
data from the current cloud VPS to a new **Linode** VPS.

**Why this is straightforward:** the whole stack is Dockerized
(`docker-compose.yml`) and all state lives in three directories (`app_data/`,
`decks/`, `uploads/`). No database dump is needed — just copy files, rebuild
images, and start.

---

## 0. What you're moving

| Item | Where | Notes |
|---|---|---|
| Source code | `/opt/novra-pdf` | The `pdf-to-slides` repo |
| `.env` secrets | `/opt/novra-pdf/.env` | Must be copied verbatim |
| Decks (pptx/mp3/pngs) | `/opt/novra-pdf/decks/` | Generated output; back it up |
| Presenton data | `/opt/novra-pdf/app_data/` | Presenton's own artifacts |
| Uploads | `/opt/novra-pdf/uploads/` | Temp; usually empty |
| Docker images | local | `presenton`, `app`, `pdf2slides-renderer` — rebuild on new host |
| Reverse proxy (Caddy/nginx) | host | Config in `/etc/caddy/` or `/etc/nginx/` |

---

## 1. Pre-flight inventory (on the CURRENT VPS)

```bash
# 1. Confirm what's running
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"

# 2. Confirm the docker-compose file and env
cd /opt/novra-pdf   # or wherever the repo lives
grep -oE '^[A-Z_]+=' .env   # lists key names only; does NOT print values
# Expected keys (at minimum):
#   CUSTOM_LLM_API_KEY, PEXELS_API_KEY, OPENAI_API_KEY,
#   TTS_URL, TTS_VOICE, PRESENTON_URL, PORT

# 3. Measure data volume size (should be small: decks + app_data)
du -sh decks app_data uploads 2>/dev/null
```

---

## 2. Backup data on the current VPS

```bash
# Tar the three data dirs + source/config files (exclude node_modules).
# NOTE: --exclude=decks/*/media and --exclude=decks/*/slides keep the archive
# small; those assets can be regenerated by re-rendering each deck.
tar -czf novra-backup-$(date +%F).tar.gz \
  -C /opt/novra-pdf \
  --exclude=node_modules \
  --exclude=decks/*/media \
  --exclude=decks/*/slides \
  .env .env.example docker-compose.yml Dockerfile renderer public server.js \
  pipeline.js package.json package-lock.json \
  app_data decks uploads

# SCP it to your local machine
scp root@<CURRENT_VPS_IP>:/opt/novra-pdf/novra-backup-*.tar.gz .

# (Optional) Skip backing up decks/ entirely if you want to regenerate —
# saves ~500MB and Presenton will rebuild each deck on demand.
```

---

## 3. Provision the Linode

1. Create a **Nanode 4GB** (`$24/mo`) or **Shared 4GB** Linode.
2. Region: closest to the school/users.
3. Image: **Ubuntu 24.04 LTS** (matches the renderer base image).
4. Add a root password or SSH key.
5. Boot.

> Note: the LibreOffice renderer (`pdf2slides-renderer`) runs as a one-shot
> `docker run` per deck and can consume ~1.5–2GB RAM during a render. A 2GB
> Linode is the bare minimum; 4GB is recommended so renders don't OOM while
> Presenton + the app are also running.

## 4. Base hardening (recommended)

```bash
ssh root@<LINODE_IP>

# System update
apt update && apt full-upgrade -y

# Create a non-root user
useradd -m -s /bin/bash novra
usermod -aG sudo novra
mkdir -p /home/novra/.ssh
cp ~/.ssh/authorized_keys /home/novra/.ssh/ && chown -R novra:novra /home/novra/.ssh

# Fail2ban + firewall (recommended)
apt install -y fail2ban ufw
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
# Do NOT open 3005/5001/8880 to the world — terminate TLS with a reverse proxy
# (Caddy) and have it forward to localhost only.
```

---

## 5. Install Docker

```bash
curl -fsSL https://get.docker.com | sh
usermod -aG docker novra
systemctl enable --now docker

# Verify
docker --version
docker compose version   # compose plugin is included in get.docker.com
```

Log out and back in (or run `newgrp docker`) so the `novra` user can use
`docker` without `sudo`.

---

## 6. Deploy the app

```bash
cd /opt

# Option A: fresh clone (recommended if the repo is on GitHub)
git clone <your-repo-url> novra-pdf

# Option B: restore from the backup tar (if the repo is not on a remote)
# mkdir /opt/novra-pdf && tar -xzf novra-backup-*.tar.gz -C /opt/novra-pdf

cd novra-pdf

# Restore .env (CRITICAL — must match old host's secrets).
# Either scp the .env from the backup, or recreate manually from .env.example.
#  scp root@<CURRENT_VPS_IP>:/opt/novra-pdf/.env ./

# Install deps
npm install

# Build the renderer image (~800MB, one-time)
npm run build:renderer

# Build the app image
docker compose build app
```

---

## 7. Restore data

```bash
cd /opt/novra-pdf

# If you used the backup tar:
tar -xzf novra-backup-*.tar.gz -C /opt/novra-pdf

# Fix ownership
chown -R novra:novra /opt/novra-pdf/decks \
                     /opt/novra-pdf/app_data \
                     /opt/novra-pdf/uploads
```

---

## 8. Start services

```bash
cd /opt/novra-pdf
docker compose up -d

# Verify
docker compose ps
# Should show: presenton (Up), app (Up). The renderer service is
# profile "build-only" and never runs as a long-running container.
```

`docker compose ps` showing the renderer as `Exit 0`/stopped is **expected** —
it's a one-shot image build target, not a service.

---

## 9. Reverse proxy (Caddy — simplest TLS)

```bash
apt install -y caddy

cat > /etc/caddy/Caddyfile <<'EOF'
pdf-api.yourdomain.com {
    reverse_proxy localhost:3005
}
EOF

systemctl enable --now caddy
```

**CORS** (so the iframe embed works from other origins). The Express app sends
`Access-Control-Allow-Origin: *` itself (see the Embed API section), so no
Caddy CORS config is needed. If you prefer to lock it down at the proxy,
replace the block above with:

```
pdf-api.yourdomain.com {
    header Access-Control-Allow-Origin *
    header Access-Control-Allow-Methods "GET, POST, OPTIONS"
    header Access-Control-Allow-Headers "Content-Type, Authorization"
    reverse_proxy localhost:3005
}
```

---

## 10. DNS

- Point an `A` record `pdf-api.yourdomain.com → <LINODE_IP>`.
- Wait for propagation, then verify:
  `curl https://pdf-api.yourdomain.com/api/health`

---

## 11. Smoke test after migration

```bash
# Health
curl https://pdf-api.yourdomain.com/api/health

# Upload a test PDF with voiceover
curl -X POST https://pdf-api.yourdomain.com/api/upload?voiceover=1 \
  -H "Authorization: Bearer $API_TOKEN" \
  -F "pdf=@test.pdf"

# If the response contains viewerUrl, open it in a browser.
# Also verify the embedded viewer from a different origin:
#   https://pdf-api.yourdomain.com/decks/<deckId>/view?embed=1
```

---

## 12. Old VPS decommission

1. Keep the old VPS running for **48h** as a fallback.
2. Before cutover, set the DNS record's **TTL low** (e.g. 60s).
3. Point DNS at the Linode and confirm traffic flows.
4. After 48h with no issues, snapshot + destroy the old VPS.

## 13. Troubleshooting the migration

| Symptom | Cause | Fix |
|---|---|---|
| `renderer` container not running | Build-only profile; never runs | Expected — it's invoked on-demand via `docker run` |
| `docker run` fails inside the app container | App container can't reach the host Docker socket | Run the app on the host (not in a container) for the renderer step, or mount `/var/run/docker.sock` into the app container |
| CORS block on the embed iframe | Server sends no CORS headers | The app now sends `Access-Control-Allow-Origin: *`; if it's still blocked, add the Caddy CORS block above |
| `pdf2slides-renderer` not found | Image not rebuilt on the new host | `npm run build:renderer` |
| Presenton 503s | Missing `CUSTOM_LLM_API_KEY` or `PEXELS_API_KEY` in `.env` | Copy the old `.env` exactly |
| Voiceover 401 | `OPENAI_API_KEY` missing | Copy from old `.env` |
| Port already in use | Old container still bound | `docker compose down` first |
| Deck images broken after migration | `decks/<id>/media` or `slides` excluded from the tar | Re-run the render for that deck (delete its `render.json` and reprocess), or copy `decks/` fully |
| Render OOM on the new host | 4GB Linode too small / too many concurrent decks | Use Shared 4GB or larger; renders run one at a time |
| App cannot `docker run` the renderer | Docker socket not exposed to the app container | Use `USE_RENDERER=0` (falls back to the text compositor) or expose the socket |

## 14. Production notes for the new host

- **Auth:** set `API_TOKEN` in `.env` to require a bearer token on
  `/api/upload` and `/api/embed` (see the Embed API section below).
- **Embed CORS:** by default the embed endpoint allows any origin. To restrict
  it, set `EMBED_ALLOWED_ORIGINS=https://yourfrontend.com,https://app.example.org`
  in `.env`.
- **Backups:** add a cron job to snapshot `decks/`, `app_data/`, and `.env`:
  `0 2 * * * tar -czf /var/backups/novra-$(date +\%F).tar.gz -C /opt/novra-pdf .env app_data decks`
- **Old decks cleanup:** add a cron job to delete `decks/*` older than N days.
- **HTTPS:** Caddy auto-provisions Let's Encrypt certs — make sure
  `pdf-api.yourdomain.com` resolves publicly before enabling it.
